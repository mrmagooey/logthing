logthing analytics stack installed as {{ include "la.fullname" . }}.

Open Hue (the first person to log in becomes the admin):
  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "la.fullname" . }}-hue 8888
  then browse http://localhost:8888

Query Trino directly:
  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "la.fullname" . }}-trino 8080

Tables appear only after the first committer run (CronJob {{ include "la.fullname" . }}-committer,
schedule "{{ .Values.committer.schedule }}") has seen flushed data.

Uninstalling leaves the PersistentVolumeClaims behind (Postgres roles and Garage keys persist
in them) but deletes the generated credentials Secret. Delete the PVCs before reinstalling
unless you supply credentials.existingSecret with the original values:
  kubectl delete pvc -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}
{{- if not .Values.credentials.existingSecret }}

Credentials were generated (or taken from credentials.*) and stored in Secret
{{ include "la.fullname" . }}-credentials. They persist across `helm upgrade`. Read one with:
  kubectl get secret -n {{ .Release.Namespace }} {{ include "la.fullname" . }}-credentials -o jsonpath='{.data.postgres-password}' | base64 -d
`helm template` cannot read the live Secret, so rendered manifests contain fresh random values:
pin credentials.* or use credentials.existingSecret when applying with GitOps tooling.
